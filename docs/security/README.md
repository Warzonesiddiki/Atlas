# Security

## Reporting vulnerabilities

We take security issues in Atlas seriously. Because Atlas is distributed as a
text‑based playbook, most issues can be discussed publicly, but if you have
found something that could put end users at risk (for example a supply‑chain
issue with bundled binaries or an elevation path in our scripts), please
**report it privately** before opening a public issue or PR:

- Email: `security@atlasos.net` (PGP key to be published here in due course)
- Expect an initial response within 72 hours.

For issues in third‑party components (AME Wizard, ViVeTool, Open‑Shell, etc.),
please report to the upstream project first — we will coordinate on a fix.

## Supply chain guarantees

Starting with v0.6.0:

- Every bundled binary is listed in `AtlasModules/Other/hashes.sha256` with its
  SHA‑256 hash. The file is generated by `scripts/ci/New-AtlasHashManifest.ps1`
  and is **verified in CI** after every build.
- A CycloneDX SBOM is shipped at `AtlasModules/Other/sbom.json`.
- GitHub Actions are pinned and kept up to date by Dependabot.
- Network downloads performed by Atlas scripts must go through
  `Get-AtlasVerifiedFile.ps1`, which enforces HTTPS (TLS 1.2+), and refuses to
  keep files whose hash does not match the expected value. Raw
  `Invoke-WebRequest`/`curl` calls are flagged by the validator.
- The auto‑commit bot only adds CABs under `AtlasModules/Packages/` and the
  hash/SBOM manifests; it cannot modify arbitrary files.

## What Atlas does *not* do

- Atlas does not ship a modified Windows image. It applies configuration to a
  stock Windows install via AME Wizard.
- Atlas does not touch Windows activation.
- Atlas does not add backdoors or "phone home" code. The project removes
  telemetry; introducing our own would defeat the purpose.
- Atlas cannot protect you from vulnerabilities in the underlying Windows
  install. Please apply security updates (available as an install‑time option
  and post‑install toggle).

## Security posture of bundled binaries

Each bundled third‑party binary (ViVeTool, multichoice, SetTimerResolution,
MeasureSleep) has its source URL and hash recorded in
`Executables/AtlasModules/README.md`. We aim to review and bump these at least
once per release cycle.
